# ADR-015: Contaminated skills are a design fault, not a model fault

**Status:** Accepted · **Date:** 2026-09-01

## Context

The first library that reached the retrieval path was measured, and it was bad:

```
approach: produce diagnosis, fix              0 successes / 26 uses   (0%)
approach: produce duration_minutes, strategy  5 successes / 27 uses  (19%)
```

Reviewing the next four candidates found three carrying their own source task —
its keys, its domain, or its answer. One clean approach in four.

The tempting reading is "the model writes bad advice". It is worth resisting,
because it leads nowhere: there is no prompt that makes a model reliably
produce advice general enough for tasks it has not seen, and believing there is
turns a fixable pipeline into an unfixable vendor problem.

## The question

Each contamination class was traced to the line that let it through.

**1. `stock_count` — an identifier naming the source task.** `strip_source_terms`
removed subject-matter WORDS by comparing against the task's vocabulary. The
token `stock_count` is not in that vocabulary; "stock" and "count" are. The
abstraction tokenised prose and never considered that a writer packs two words
into one identifier. **Design.** The model wrote a perfectly ordinary step.

**2. `<NUMBER>! = 6` — a computed answer.** The NUMBER pattern ended
`(?![\w.])`, rejecting a following period so `1.25` would not be split in half.
It also rejected the period that ends a sentence, so a number in final position
was invisible: `"the answer is 42."` yielded no literals at all. The end of a
sentence is where an answer gets stated. **Design**, and a two-character one.

**3. Advice about synthetic probes and real-user monitoring.** Distillation
abstracts the PLAN STEP, and the plan step is prose written for one task by a
planner that knows the domain. Abstraction removes literals and words the task
used. It cannot remove domain knowledge the planner introduced, because
"domain" is not a structural property — `probes` and `monitoring` look exactly
like `parse` and `validate` to any rule that does not already know the subject.
**Design**, and the deepest of the three: the pipeline asks for prose to
generalise and provides no mechanism that makes it.

Zero of three were model faults. In every case the model did what it was asked
and the pipeline failed to enforce the property it needed.

## The deeper fault

Distillation is the one place in this system that **trusts instead of
verifying.** Everything else is criterion-first (ADR-009): a claim is not
believed until something independent checks it. A skill makes a claim — *this
approach transfers* — and until it is retrieved, nothing tests it. It goes into
future worker prompts on the strength of having been distilled.

That is why the failure was invisible for so long, and why it cost 26
retrievals to surface.

## Decision

**Fix what is structurally detectable, deterministically.**

*Identifiers.* `strip_source_terms` splits on the boundaries a writer actually
put there — `_`, `-`, camelCase — and strips a token when every part came from
the task and not all parts are method vocabulary. `stock_count` collapses;
`sort_by_price` survives, because an identifier made only of method words is
describing the work rather than the thing worked on.

*Sentence-final numbers.* The NUMBER guard now rejects a following period only
when it is a decimal point.

**Do not pretend the third class is detectable.** A signal was built and
measured before being adopted: the share of an instruction's content words
appearing in neither the task nor the method lexicon. Across the four judged
candidates it read 0.41, 0.52, 0.35 for the three rejects and 0.33 for the one
approval. That does not separate them. Shipping it would mean tuning a
threshold on four samples to reproduce a judgement already made by hand, which
is how a metric becomes a rationalisation. Rejected.

**Make the empirical control cheap instead.** The mechanism that *did* catch
these skills is the one that measures them in use: retrieval scoring and
pruning. It worked — both were retired automatically with the reason on the
record. It was slow only because `prune` runs at consolidation, every N tasks,
while a skill can be retrieved by every node of every task in between.

So retrieval now applies the same rule against the same constants: a skill at
or past `PRUNE_MIN_USES` with a success rate below `PRUNE_MIN_SUCCESS_RATE` is
not offered, even before consolidation formalises the retirement. The damage a
bad skill can do is capped at the evidence threshold rather than at the
consolidation interval. Consolidation still does the retiring; this only stops
the bleeding.

## Consequences

**The remaining exposure is bounded and named.** Domain-as-method still reaches
the library. It costs at most `PRUNE_MIN_USES` retrievals before the record
withdraws it, and the human gate sees it first — which is exactly how the
uptime-probes candidate was caught.

**The human gate is load-bearing, and its signals are weak.** `generality`
scored **1.00** on the worst candidate in the set — the one naming another
task's keys. It measures method-vocabulary density, which contamination does
not reduce. A reviewer reading the instruction catches these; a reviewer
reading the score does not. Anything that automates approval on that score
would have admitted all three.

**There is a design that would eliminate the class outright**, and it is not
taken here: build the instruction from structured parts only — the artifact
shape, the check kinds, the method verbs — and never embed the step's prose.
No prose, no leaks, by construction. It is not taken because the prose is what
tells a worker HOW, and trading all of it for cleanliness is a bet that should
be settled by measurement rather than by argument. The comparison is worth
running once the library is large enough for an ablation to discriminate.

**And the honest summary for anyone reading the 0/26:** that number is not
evidence that skill retrieval does not work. It is evidence that three
specific, identified pipeline defects produced advice that could not work, two
of which are now closed.
