# ADR-016: Advice is served only where a second task shape corroborates it

**Status:** Accepted · **Date:** 2026-09-02

## Context

ADR-015 closed three of four skill-contamination channels deterministically and
refused to pretend the fourth was detectable. Domain-as-method — advice about
`synthetic probes and real-user monitoring` distilled from an uptime task and
then offered to a warehouse one — has no structural signature. `probes` and
`monitoring` are the same shape of token as `parse` and `validate` to any rule
that does not already know the subject. A detector was built, measured across
the four judged candidates (0.41 / 0.52 / 0.35 for the rejects against **0.33**
for the approval) and rejected, because shipping it would have meant tuning a
threshold on four samples to reproduce a judgement already made by hand.

That left the class reaching the library, bounded only by `PRUNE_MIN_USES`
retrievals and the human gate.

ADR-015 also named the deeper fault behind it: **distillation is the one place
in this system that trusts instead of verifying.** Everything else is
criterion-first (ADR-009) — a claim is checked by something independent before
it is believed. A skill makes the claim *this approach transfers*, and nothing
tested it before it entered worker prompts.

## Decision

**Serve only the words a second, differently-shaped task also used.**

The promotion bar already requires evidence from `MIN_DISTINCT_TASKS` distinct
task shapes (ADR-014). What that bar was throwing away is that each of those
shapes produced *its own wording* of the approach. Two independent wordings of
one approach are exactly the instrument this class needs:

- contamination is **one task's vocabulary by construction** — it is in the
  advice because that task's planner knew that subject;
- so it cannot appear in the other shape's wording, unless the other task
  genuinely called for it too, in which case it is not contamination.

`Skill.evidence_instructions` records the wording each contributing shape
distilled. `Skill.served_instruction` — what a worker is shown and what a
reviewer approves — reports the vocabulary every recorded wording used.
`generalise.corroborated_terms` computes it.

### The intersection is served as a set, not as a sentence

The first implementation kept one wording's grammar and deleted its unattested
words. On the first real pair — a timezone-filter step and an HTTP-header step
that distilled to the same approach — it produced:

```
When a step calls for this: <>-check the `` from the <> (if any) with the `<>`
values from the <>. Output a `` if the <>' filter all records to <> time.
```

The contamination was gone and so was the meaning. Filtering a sentence
produces text neither task wrote, and punctuation around holes reads as a
system malfunctioning rather than as advice.

An intersection is a **set**. Served as one, labelled as one:

```
When a step calls for work of this kind: 3 differently-shaped tasks described
this approach with: check, filter, output, records, values. Produce a JSON
object whose values are of these kinds: str. Take the KEY NAMES from your own
criterion, never from here.
```

The count is of WORDINGS, not of evidence shapes: a shape can accrue through
`record_evidence`, which carries only a fingerprint, and a shape that
contributed no wording corroborated nothing.

Nothing here decides what a domain word is. There is no threshold, no lexicon
of subjects, no score. A word is kept because more than one task shape used it.

### What is deliberately not touched

- **`Skill.instruction` stays verbatim.** It is half of the content address
  (`make_skill_id`), so rewriting it would fork the identity that ADR-014
  exists to keep whole. Corroboration is a read-time projection.
- **Method vocabulary is NOT exempt.** Whether both tasks described the work
  the same way is precisely the question, and a method word only one of them
  used is that task's account of the work rather than the approach. Function
  words and placeholders are excluded from both sides: a placeholder marks
  where one task's literal stood, which is the definition of what cannot be
  corroborated.
- **A single wording is served unchanged.** A wording corroborated against
  itself would *look* verified. `merge_identity` replays one record's
  instruction once per shape it had accrued, so recorded wordings are
  de-duplicated before the count is taken — a migrated library gets the
  fallback, not a false claim.

### When nothing survives

If no prose word is attested twice, the served instruction keeps only the part
generated from structure — the artifact's value kinds and the warning to take
key names from the reader's own criterion — and says nothing else.

That is the "structured parts only" instruction ADR-015 described as the design
that would eliminate the class outright and declined to adopt wholesale,
because prose is what tells a worker *how*. This reaches it **per skill and by
evidence**: advice keeps the prose two tasks agreed on, and falls back to
structure exactly where it has none.

## Consequences

- The class is closed at the point of service rather than bounded after the
  fact. A contaminated wording can still be distilled and stored; it cannot be
  served, and a reviewer no longer approves text that differs from what workers
  will receive.
- **The cost is real and one-directional**: genuinely useful method vocabulary
  that only one shape happened to use is dropped too. Corroboration cannot tell
  a load-bearing word from a domain word — it only knows how many tasks said
  it. The trade is deliberate: an over-general instruction is ignorable, and a
  confidently wrong one is not.
- Evidence beyond the second shape sharpens it further, at no extra cost: each
  additional wording narrows the intersection.
- `MAX_EVIDENCE_TASKS` now bounds two lists rather than one. Both are written
  into a record a human reads, and both stay bounded for that reason.
