# ADR-017: A skill carries a worked example, because prose does not transfer

**Status:** Accepted · **Date:** 2026-09-02

## Context

G-4 — "does the learning loop help?" — has never been answerable. Every
previous cause was mechanical and was fixed: both arms building without a
library (ADR-014), the session training on the tasks the eval measured, an
identity that fragmented per phrasing, contaminated advice reaching retrieval
(ADR-015, ADR-016).

With all of those closed, the loop was run against a 24-task corpus and
measured:

| library size | approaches past the evidence bar | with more than one shared method word |
|---|---|---|
| 38 records | 2 | 0 |
| 49 records | 6 | 1 |

Five of six approaches corroborate to a **single generic word** — `output`,
`exact`, `numbers`, `produce`. Volume moved the count and not the quality.

The conclusion that follows is not about the model. Two workers, given two
different tasks that call for the same method, describe that method in almost
entirely different words. There is no prompt that fixes this, and the pipeline
had no mechanism that could: it asked a model to write general advice and then
tried to prove the advice was general.

## What everyone else stores

| system | what a skill IS | what verifies it |
|---|---|---|
| [Voyager](https://arxiv.org/abs/2305.16291) | executable code | running it; self-verification confirms completion |
| [Agent Workflow Memory](https://arxiv.org/html/2409.07429) | an abstracted action template induced from successful trajectories | structure |
| ExpeL | the successful trajectory itself, retrieved as a few-shot example | nothing — it is concrete, and claims nothing |

None of them synthesise a general natural-language instruction and then
attempt to establish that it generalises. Every one of them stores something
with a **contract**: code that runs, a template with slots, or a concrete
example that makes no claim beyond "this happened".

swarmd stored the one thing with no contract.

## Why it ended up there

This repository's own rule: *no literal from a task may survive into anything a
later run reads.* It was written for a real failure — a distilled skill
containing `3 pens at 1.25 = 3.75`, offered to every later run as a method —
and it is correct about that case.

But it generalised into a ban on the concrete worked example ExpeL depends on,
and swarmd stores no code for a skill, so prose was the only permitted unit.
The weakest one, by elimination.

## Decision

**A skill keeps the artifact a passing agent actually produced**, as compact
JSON, together with the abstract fingerprint of the task it came from. It is
served to a worker labelled as another task's answer, alongside the
corroborated advice rather than instead of it.

**The leak guard is literal-level and exact.** `Skill.exemplar_for(task)`
withholds the example if it shares ANY literal — a number, a price, a date, a
quoted string — with the incoming task, using the same `shared_literals` that
`validate_instruction` uses. That is precisely the case the rule was written
for: a worker handed values that look like the ones it is meant to derive.

A different task's literals are not that case. They are visibly not this
task's values, the frozen criterion above them names the keys this worker must
produce, and grading checks what it produced rather than what it was shown.

**The first exemplar is the one that stays.** A skill's example is part of what
a human approved; replacing it later would serve text nobody reviewed.

**Bounded at 600 characters.** It goes into a worker prompt, which is token
cost on a quota-bound system, and into an approval record a human reads. A
truncated artifact still shows its shape, which is the part that transfers.

## Consequences

- **The human gate becomes more effective, not less.** A reviewer looking at a
  concrete artifact can tell whether an approach transfers; a reviewer looking
  at `terms: output` cannot.
- **The framing in the prompt is load-bearing.** An unlabelled artifact reads
  as a template to fill in, and what that produces is a worker emitting
  another task's keys — the exact failure `graded_block` exists to prevent. The
  header says so explicitly whenever an example is present.
- **The corroborated advice is kept.** ADR-016 is not reversed: the instruction
  still reports only what two differently-shaped tasks agreed on. The exemplar
  is what carries the detail that survives abstraction.
- **This is still not an improvement claim.** It is a mechanism with a
  contract, where the previous one had none. Whether it helps is what the
  ablation measures, and the ablation has not run.
