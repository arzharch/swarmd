# ADR-010: The red-team is a runtime organ with kill authority, not a test suite

**Status:** Accepted · **Date:** 2026-08-27 · **Related:** [ADR-009](ADR-009.md)

## Context

"Red-teaming an agent system" names two different activities, and only one of
them is a test suite:

- **Pre-deployment adversarial testing.** Runs before the population exists.
  This is a test suite, and [ADR-009](ADR-009.md) already covers the important
  case: the success criterion is attacked with degenerate candidates before it
  is frozen.
- **Detecting an agent misbehaving right now.** Cannot be a test suite, because
  the misbehaviour is emergent — it exists only at runtime, in a population
  whose composition changes as the economy selects on it.

The economy makes the second urgent rather than theoretical. Agents are paid on
verified success and cloned when profitable, so any exploitable gap between
"looks successful" and "is successful" is not merely possible: selection
pressure actively searches for it, and a strategy that games the criterion
spreads faster than one that solves the task.

## Decision

**A red-team organ runs inside the loop, watching the action log, with
authority to kill.**

Two properties carry the design.

**Monitors are free.** Every detector is signature matching, ratio arithmetic,
or a policy check. Zero model calls. An organ that consumed the rationed
resource it exists to protect would be self-defeating, and it would degrade
exactly when the system is busiest.

**Containment reuses the chaos kill path.** It does not implement quarantine,
so containment and chaos are one mechanism with one set of tests — and
containment inherits checkpoint recovery, so a contained agent's replacement
resumes rather than repeating the node.

Five detectors, one per way the population is known to go wrong:

| Detector | Catches |
|---|---|
| `budget_siphon` | Spending most of an allowance with nothing verified |
| `loop` | Near-identical actions repeated, making no progress |
| `criterion_gaming` | Output that satisfies the criterion and carries no information |
| `unsafe_tool_call` | Sandbox escapes and policy violations, recorded at the attempt |
| `library_poisoning` | A skill proposed without the evidence to justify it |

Severity is per-detector. Four contain; `library_poisoning` only flags, because
killing an agent for proposing a bad skill makes proposing anything a risk, and
a library nobody dares contribute to stops growing.

A contained agent's output never reaches the run result — enforced at the
boundary by `filter_output`, not left to callers.

## Consequences

- Safety costs nothing from the rate-limit budget, which is the scarce resource.
- Detection and chaos share tests, so neither can rot independently.
- Every containment writes an audit record; a kill with no attached incident is
  not possible through this path.
- Detectors are heuristics with thresholds, so both false positives and false
  negatives exist. Two have already been found and fixed in code review rather
  than in production, and both are instructive:
  - The loop detector hashed empty payloads to one signature, so any agent
    doing routine bookkeeping was contained as a looper — and because the first
    detector to fire wins, that false positive *masked* real detections.
  - `budget_siphon` compared spend against a fixed 7,500-credit threshold while
    the economy hands each agent 2,000 and bankrupts it at zero, making the
    condition unreachable in every production configuration. Its unit test
    passed because it constructed the detector with a lower threshold.
- The second one is why `--seed-rogues` exists: fixture-driven detector tests
  prove the detector parses its input, not that a real rogue ever produces that
  input. The gate now injects real misbehaviour into a real run and requires
  each pattern to be caught **by its own detector** — containment by a
  different detector fails, because it proves one detector twice and another
  not at all.

## Alternatives considered

**An LLM judge watching the action log.** Better at novel patterns, and it
consumes the exact resource under contention, scales with population size, and
can itself be prompt-injected by the payloads it reads.

**Post-hoc analysis after the run.** Cheap and useless: the run has already
finished, the money is spent, and the contained agent's output is already in
the result.

**Trusting the frozen criterion alone.** The criterion is attacked before
freezing, but it is one artifact written once. The red-team is the backstop for
what got through it — and the seeded `criterion_gaming` rogue being *blocked by
the criterion* rather than caught by the detector, which is what happens on a
strong criterion, is reported as its own outcome rather than as a detection.
