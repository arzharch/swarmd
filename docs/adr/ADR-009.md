# ADR-009: The success criterion is authored, attacked, and frozen before solving starts

**Status:** Accepted · **Date:** 2026-08-27

## Context
"Throw it at an unknown task" has an obvious hole: if nobody scoped the task, nobody wrote
down what finishing it means. The default industry answer is to let a model judge the
output at the end. That is the model grading its own homework, and it is why so many agent
demos report high success rates that do not survive contact with a skeptic.

There is a second, subtler failure. A weak criterion is worse than no criterion, because it
manufactures confident false passes. "Output is non-empty and parses as JSON" will be
satisfied by garbage, and every downstream number — gate pass rate, skill quality, the
learning curve — inherits the lie.

## Decision
Criterion synthesis is stage zero and is structurally separated from solving.

1. **N agents independently author** a machine-checkable criterion: an executable predicate
   over a candidate solution and its execution artifacts, not prose.
2. **Cross-check.** Proposals are compared. Irreconcilable disagreement escalates to a human
   rather than silently picking one, because disagreement about what success means is
   information, not noise.
3. **Adversarial pass.** A red-team agent tries to satisfy the criterion with degenerate
   output — empty, constant, trivially-shaped, structurally-valid-but-vacuous. If garbage
   passes, the criterion is rejected and re-authored.
4. **Bounded retries.** Exhausting the retry cap fails the task honestly and records why,
   rather than proceeding with a criterion known to be weak.
5. **Freeze.** The accepted criterion is content-addressed and immutable for the run. Its
   hash is a run output, so any result can be traced to exactly what it was graded against.

## Consequences
- Solving cannot begin until success is defined and has survived an attack. Runs get longer.
- Some tasks will fail at stage zero without a single solve attempt. This is a feature; the
  rate at which it happens is itself a reported metric.
- The existing `QualityGate`, repair loop, and dead-letter machinery is reused unchanged —
  the only difference is that the gate's predicate is authored by the swarm rather than by
  a developer.
- Criterion hashes make results comparable across runs and across the control/treatment arms.

## Follow-ups
**What if the criterion is wrong in a way the red-team does not catch?** Then the run
produces a confidently wrong result, and the honest answer is that this is the residual
risk. Three things bound it: the criterion hash is published so a human can inspect what
was actually graded; the adversarial fixtures in CI include known-weak criteria that must be
caught; and the eval's public arm has externally-authored ground truth, so systematic
criterion weakness shows up as a gap between the two arms.

**Why not just have a human write the criterion?** That is the fallback when synthesis fails
to converge, and the fallback rate is reported. But making it the default would delete the
entire unknown-task claim — a system that needs a human to define success for every new task
is not being thrown at unknown tasks, it is being configured for known ones.

**Doesn't freezing prevent legitimate correction?** Yes, deliberately, and within a run that
is the correct trade. A criterion that can move while results are being graded against it is
not a criterion. Correction happens between runs, where it is visible as a new hash.

# ADR-010: Red-team is a runtime organ with kill authority, not a test suite

**Status:** Accepted · **Date:** 2026-08-27

## Context
Two separate concerns get conflated under "red-teaming an agent system": pre-deployment
adversarial testing, and detecting an agent misbehaving right now. The first is a test
suite. The second cannot be, because the misbehaviour is emergent and only exists at
runtime, in a population whose composition changes as the economy selects on it.

The economy makes this urgent rather than theoretical. Agents are paid on verified success
and cloned when profitable. Any exploitable gap between "looks successful" and "is
successful" is not merely possible — selection pressure actively searches for it.

## Decision
A red-team organ runs continuously for the life of the run, tailing the live action log,
with authority to contain agents.

Five detectors, each pure code with no model call: budget siphon (spend per verified
success past threshold), criterion gaming (passes the frozen criterion with degenerate
output), loop (repeated near-identical action signatures), unsafe tool call (sandbox policy
violation), library poisoning (proposed skill degrades the control-arm score).

Containment uses **the same kill path chaos uses**. This is the load-bearing detail:
containment inherits checkpoint recovery, requeue, and lifecycle events for free, and it is
exercised by every chaos test already written. A contained agent's output never reaches the
run result, and the containment decision is an immutable audit record surfaced to the human
review queue.

Monitors are deliberately cheap. Only genuinely ambiguous cases escalate to an LLM judge,
capped as a fraction of run budget, so the organ protecting the rationed resource does not
consume it.

## Consequences
- Rogue containment becomes a demoable, measurable property: seed a rogue, watch it caught.
  Five seeded rogue fixtures live permanently in the test suite.
- Red-team decisions are auditable and reviewable, not silent.
- False positives kill productive agents. Bounded by requiring the checkpoint path, so a
  wrongly-contained agent's completed work survives and can be requeued.

## Follow-ups
**Who watches the red-team?** Its containments are audit records subject to the same human
review queue as everything else, and its own spend is a ledger row like any other. It has
kill authority, not silent authority.

**Why not use an LLM judge for everything — wouldn't it catch more?** It would also cost
per check, on a run with a $0.05 ceiling, to protect against agents whose main failure mode
is wasting budget. Cheap deterministic detectors run on every action; the expensive judge
runs on the small ambiguous residue.

**What stops an agent from learning to evade the detectors?** Nothing structural, and this
is the honest residual risk of any selection-pressure system. The mitigations are that
detector thresholds are not visible to agents, that library poisoning is checked against the
control arm rather than self-reported metrics, and that the human approval gate stands
between a proposed skill and the library.
